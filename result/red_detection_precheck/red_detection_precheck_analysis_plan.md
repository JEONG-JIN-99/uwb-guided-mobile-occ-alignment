# 빨간색 인식 사전검사 통합 분석 계획

## 1. 목적

정적 정렬 실험의 본격적인 성능 지표를 산출하기 전에, 카메라와 빨간색
검출기의 기본 성능을 거리별로 확인한다. 1 m, 2 m, 3 m에서 각각 사전검사를
3회 수행하고, 같은 거리의 세 실행 결과를 합산하여 다음 두 지표를 산출한다.

1. 전체 인식률
2. 카메라 프레임 수신 조건부 인식률

이 사전검사는 짐벌 정렬이나 UWB 성능을 평가하는 실험이 아니다. 카메라가
새 프레임을 제공했는지와, 제공된 프레임에서 빨간색 표식을 검출했는지를
분리하여 이후 정적 정렬 실험의 인식 실패 원인을 해석하기 위한 기준값을
만드는 것이 목적이다.

---

## 2. 실험 구성

각 거리에서 `red_detection_precheck.py`를 100회씩 3번 독립 실행한다.

| 거리 | 실행 횟수 | 실행당 시도 | 거리별 총 시도 |
|---:|---:|---:|---:|
| 1 m | 3 | 100 | 300 |
| 2 m | 3 | 100 | 300 |
| 3 m | 3 | 100 | 300 |

전체 분석 대상은 9개 실행, 총 900회다. 각 실행은 별도의
`run_<timestamp>_distance_<distance>m_crop_<scale>/` 폴더와
`red_detection_results.csv`를 가져야 한다.

세 반복 사이에는 다음 조건을 동일하게 유지한다.

- 카메라와 표식의 위치 및 방향
- 카메라 장치 번호
- 조명 조건
- `crop_scale`
- 회차별 인식 제한시간 `interval`
- 카메라 워밍업 시간
- 빨간색 HSV 임계값
- 전체 빨간 마스크 최소 면적
- 최대 연결 빨간 영역 최소 면적

조건이 달라진 실행은 같은 거리의 합산 대상에 넣지 않는다. 불가피하게 조건이
달라졌다면 별도 조건으로 분리하고 그 이유를 기록한다.

---

## 3. 입력 데이터 선택 및 검증

분석 전에 1 m, 2 m, 3 m별로 사용할 실행 폴더를 정확히 3개씩 명시한다.
폴더의 이름이나 생성 시각만으로 자동 선택하지 않고 각 CSV의 내용을
검증한다.

각 CSV는 다음 조건을 만족해야 한다.

- 행 수가 정확히 100개다.
- `attempt`가 1부터 100까지 중복이나 누락 없이 존재한다.
- `distance_m`가 해당 분석 거리와 일치한다.
- `target_color`가 모두 `red`다.
- `status`가 `success`, `color_not_detected`,
  `camera_frame_timeout` 중 하나다.
- 세 실행의 카메라 및 빨간색 검출 조건이 동일하다.
- 중단되었거나 일부 회차만 기록된 실행이 아니다.

검증에 실패한 실행을 임의로 포함하거나 다른 실행으로 자동 대체하지 않는다.
어떤 실행을 제외했는지와 재실험 필요 여부를 기록한다.

---

## 4. 거리별 합산 방법

거리 \(d\)의 세 실행에서 다음 건수를 먼저 합산한다.

```text
N_d = 세 실행의 전체 시도 수 합계
S_d = status == "success" 수 합계
C_d = status == "color_not_detected" 수 합계
F_d = status == "camera_frame_timeout" 수 합계
```

정상적인 분석에서는 거리마다 `N_d = 300`이어야 하며 다음 등식을 검증한다.

```text
N_d = S_d + C_d + F_d
수신 프레임 평가 수 = S_d + C_d = N_d - F_d
```

세 실행에서 계산한 인식률을 단순 평균하지 않는다. 실행마다 성공과 실패
건수를 먼저 합산한 뒤 합산 건수로 거리별 인식률을 계산한다. 정상적으로 모든
실행이 100회라면 단순 평균과 값이 같을 수 있지만, 논문용 결과의 재현성과
분모를 명확히 하기 위해 반드시 합산 건수를 사용한다.

### 4.1 전체 인식률

```text
전체 인식률_d = S_d / N_d × 100
```

전체 300회를 분모로 사용한다. `color_not_detected`와
`camera_frame_timeout`을 모두 실패로 포함하므로, 이 값은 빨간색 검출 성능과
카메라 프레임 가용성을 함께 반영하는 시스템 수준의 인식률이다.

### 4.2 카메라 프레임 수신 조건부 인식률

```text
프레임 수신 조건부 인식률_d = S_d / (S_d + C_d) × 100
```

제한시간 안에 새 카메라 프레임을 실제로 받은 회차만 분모로 사용한다.
`camera_frame_timeout`은 제외하고, 수신 프레임에서 빨간색 검출기가 표식을
인식했는지를 평가한다. `S_d + C_d = 0`이면 0%가 아니라 `N/A`로 표시한다.

## 5. 논문용 결과 형식

최종 결과는 거리별 합산 건수와 두 인식률을 하나의 표로 제시한다.

| Distance (m) | Total attempts | Successful detections | Color not detected | Camera frame timeouts | Overall recognition rate (%) | Frame-conditional recognition rate (%) |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 300 | ... | ... | ... | ... | ... |
| 2 | 300 | ... | ... | ... | ... | ... |
| 3 | 300 | ... | ... | ... | ... | ... |

논문 본문이나 그림에서는 기존 형식처럼 거리별로 다음 두 행만 강조할 수 있다.

| Color detection performance | 1 m | 2 m | 3 m |
|---|---:|---:|---:|
| Overall recognition rate | S/N (...) | S/N (...) | S/N (...) |
| Frame-conditional recognition rate | S/(S+C) (...) | S/(S+C) (...) | S/(S+C) (...) |

건수는 정수로 표시하고 인식률은 기본적으로 소수점 첫째 자리까지 표시한다.
CSV에는 반올림 전 계산값을 보존한다. 표와 분석 문서의 수치가 동일한 합산
건수에서 계산되었는지 확인한다.

계획 산출물은 다음 위치에 둔다.

```text
result/red_detection_precheck/
├── red_detection_precheck_analysis_plan.md
├── red_detection_precheck_aggregate.csv
├── red_detection_precheck_performance_table.png
├── red_detection_precheck_performance_table.pdf
└── red_detection_precheck_analysis.md
```

현재 문서는 계획만 정의한다. 실제 CSV·표·분석 문서는 거리별 3회 실험이 모두
완료되고 입력 실행이 확정된 뒤 생성한다.

## 6. 결과 해석 계획

### 6.1 전체 인식률 해석

전체 인식률은 설정한 제한시간(기본 0.2초) 안에 새 프레임을 받고 빨간색
검출까지 성공한 비율이다. 거리에 따라 이 값이 낮아지면 먼저
`color_not_detected`와 `camera_frame_timeout` 중 어느 실패가 증가했는지
분리해서 확인한다. 전체
인식률만으로 거리 증가에 따른 색상 검출 성능 저하를 단정하지 않는다.

### 6.2 프레임 수신 조건부 인식률 해석

프레임 수신 조건부 인식률은 카메라 프레임이 정상적으로 제공된 상황에서의
빨간색 검출 성능이다. 이 값이 거리 증가에 따라 낮아지고
`color_not_detected`가 증가한다면, 표식의 영상 내 크기 감소나 조명·임계값의
영향 가능성을 검토한다. 다만 해당 원인을 추가 데이터 없이 확정하지 않는다.

### 6.3 두 인식률의 차이 해석

전체 인식률보다 프레임 수신 조건부 인식률이 높고 두 값의 차이가 크다면,
색상 검출 실패보다 카메라 프레임 타임아웃이 전체 성능 감소에 더 크게
기여했음을 의미한다. 두 값이 비슷하게 낮다면 프레임을 받은 뒤 발생한
`color_not_detected`의 비중을 확인한다.

### 6.4 거리별 비교

1 m, 2 m, 3 m의 두 인식률과 실패 건수를 함께 비교한다. 거리 증가에 따른
단조로운 변화가 있는지 확인하되, 각 거리의 촬영 시각과 조명 조건이 완전히
동일하지 않을 수 있으므로 거리만을 직접 원인으로 단정하지 않는다.

### 6.5 세 반복의 일관성 확인

논문용 대표값은 거리별 300회 합산 결과지만, 합산 전에 각 100회 실행의
성공·미검출·타임아웃 건수도 내부 검증용으로 비교한다. 특정 실행 하나에
실패가 집중되면 일시적인 카메라 상태나 환경 변화 가능성을 기록한다. 실행별
인식률이나 표준편차는 필요할 경우 품질 확인에만 사용하며, 별도의 주요 논문
지표로 추가하지 않는다.

### 6.6 정적 정렬 실험과의 연결

사전검사에서 프레임 수신 조건부 인식률이 높다면, 이후 정적 정렬 실험의
`color_not_detected`를 검출기 자체의 기본 실패만으로 설명하기 어렵다. 정렬
직후 촬영 시점, 짐벌 이동에 따른 모션 블러, 표식의 시야 내 위치 등을 함께
검토한다. 반대로 사전검사부터 특정 거리의 조건부 인식률이 낮다면 정적 정렬
결과를 해석할 때 해당 거리의 기본 검출 한계를 함께 명시한다.

## 7. 분석 실행 순서

1. 1 m, 2 m, 3 m에서 각각 100회 사전검사를 3번 완료한다.
2. 거리별로 분석에 사용할 실행 폴더 3개를 명시한다.
3. 9개 CSV의 행 수, 거리, 대상 색상, 상태값 및 실험 조건을 검증한다.
4. 각 실행의 `success`, `color_not_detected`, `camera_frame_timeout`을 센다.
5. 같은 거리의 세 실행 건수를 합산하고 `N = S + C + F`를 검증한다.
6. 거리별 전체 인식률과 프레임 수신 조건부 인식률을 계산한다.
7. 거리별 3행 상세 표와 기존 형식의 2행 논문용 표를 생성한다.
8. 실행별 편차를 내부 검증하고 특정 실행에 실패가 집중되는지 확인한다.
9. 두 인식률과 실패 원인을 근거로 거리별 및 종합 해석을 작성한다.
10. CSV, 표 이미지, 분석 문서의 건수와 백분율이 서로 일치하는지 검증한다.

---

## 8. 최종 검증 체크리스트

- [ ] 거리별로 정확히 3개 실행을 선택했다.
- [ ] 각 실행이 정확히 100회이며 거리별 전체 분모가 300회다.
- [ ] 전체 분석 대상이 9개 실행, 총 900회다.
- [ ] 모든 CSV의 거리, 대상 색상 및 검출 조건을 검증했다.
- [ ] 모든 회차가 세 상태 중 정확히 하나로 분류되었다.
- [ ] 거리별로 `N = S + C + F`가 성립한다.
- [ ] 세 실행의 비율을 평균하지 않고 건수를 먼저 합산했다.
- [ ] 전체 인식률을 `S/N`으로 계산했다.
- [ ] 프레임 수신 조건부 인식률을 `S/(S+C)`로 계산했다.
- [ ] 카메라 타임아웃을 전체 인식률에는 포함하고 조건부 인식률에서는 제외했다.
- [ ] 두 인식률의 차이를 실패 원인 건수와 함께 해석했다.
- [ ] 거리 증가를 성능 변화의 직접 원인으로 과장하지 않았다.
- [ ] 실행별 결과를 확인하여 특정 반복에 실패가 집중되는지 검증했다.
- [ ] 결과 표, CSV 및 분석 문서의 수치가 서로 일치한다.
